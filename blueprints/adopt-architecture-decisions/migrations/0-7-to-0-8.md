# Upgrade the ADR bundle to okf-profiles v0.8.0

Move this repository's existing `docs/adr` bundle onto the v0.8.0
architecture-decision profile, which targets **Open Knowledge Format v0.2**. The
bundle already exists and already validates against an older profile — this edge
changes the pin and adds the provenance frontmatter v0.2 requires. Do not re-run
adoption, do not renumber ADRs, and do not restructure the bundle.

The exit condition is that the repository's own ADR check passes under
`--strict`.

## First: establish where this repository actually is

Do not trust the `--from` version that invoked this edge. Read
`docs/adr/profile.dhall` and find the `okf-profiles` tag it pins. That tag is
the real starting point.

- Pinned tag is **v0.7.0** — proceed.
- Pinned tag is **older than v0.7.0** — you are in the wrong edge. Run the
  `0.6.0 -> 0.7.0` edge first; a wider `--from` window selects both, in order.
- Pinned tag is **already v0.8.0** — the pin needs no change. Skip to
  *Bring the corpus up to OKF v0.2*; the corpus may still be failing.
- **No `docs/adr/profile.dhall`, or it does not pin `okf-profiles`** — this
  repository never adopted the shared profile. Stop and report that
  `seihou agent run adopt-architecture-decisions` is the correct entry point,
  not this migration.

Also check whether the descriptor has been customized. A project may have added
its own overrides on top of the imported profile. Preserve every such override;
only the pinned tag, its hash, and the now-redundant presence override described
below are yours to change.

Run the repository's ADR check now and keep the output. You need to know which
failures you inherited, and the check command itself — often a `just`, `make`,
or `npm` target wrapping `okf validate`. If none exists, use:

```sh
okf validate docs/adr --strict --profile docs/adr/profile.dhall \
  --profile-enforce --log-enforce
```

## What v0.8.0 changes

v0.8.0 moves the profile from OKF v0.1 to OKF v0.2. v0.2 assumes a corpus
written and maintained by agents, and it adds the frontmatter a reader needs to
judge machine-written knowledge. Four things change what passes.

**`generated` becomes required.** Every ADR must record who produced its current
content. This is the single largest repair in this edge — a corpus that has
never carried the key fails on every concept:

```text
profile: 0001-use-stable-identifiers: missing profile-required field: generated (§5.2. Who produced this decision record's current content, and when.)
profile: 0002-keep-local-links: missing profile-required field: generated (§5.2. Who produced this decision record's current content, and when.)
```

The shape is a mapping with a required `by` and a recommended `at`:

```yaml
generated:
  by: human:nadeem
  at: "2026-05-04T21:43:01Z"
```

`by` must match OKF v0.2 §7's actor convention, case-sensitively. A bare name is
rejected:

| Value | Verdict |
|-------|---------|
| `human:nadeem` | a person |
| `process:schema-sync` | an automated process |
| `claude-code/2.1.0` | a `<producer>/<version>` pair |
| `nadeem` | **rejected** — matches none of the three shapes |

The diagnostic when it is wrong names the member and the format:

```text
profile: <concept>: frontmatter value at generated.by must match format actor, found: "nadeem"
```

**The bundle must declare its dialect.** v0.8.0 sets
`requireBundleVersion = Some "0.2"`, so a bundle whose root `index.md` does not
declare `okf_version: "0.2"` produces a deviation that names no concept at all,
which makes it easy to misread as unrelated noise:

```text
profile: bundle does not declare okf_version; this profile requires 0.2 or later
```

**`timestamp` is demoted, not removed.** It moved to the profile's `optional`
list. A document may keep it; its RFC3339-UTC format is still checked whenever
it is present; its absence is never reported, in any mode. **Do not delete
`timestamp` from the corpus.** The instinct on reading "v0.2 supersedes
`timestamp`" is to strip the key everywhere — that is unnecessary churn on a
large corpus, and it loses information wherever `generated.at` and `timestamp`
genuinely differ.

**`verified` becomes available and is demanded nowhere.** It records independent
confirmation that the content is accurate — a list of `{by, at}` mappings, or
one bare mapping, with `by` under the same actor rule. Nothing fails if it is
absent. Add it only where the repository has real evidence someone confirmed a
decision; do not manufacture confirmations.

**One relaxation you may now inherit.** v0.8.0 folds the presence-class override
this blueprint used to ship into the upstream profile itself: `supersedes`,
`supersededBy`, and `originatingPlan` are `optional` in
`profiles/documentation/architecture-decisions.dhall` as shipped. If
`docs/adr/profile.dhall` carries the local override this blueprint installed at
v0.7.0 —

```dhall
in  base
    //  { frontmatter =
            base.frontmatter
        //  { recommended = [] : List Profiles.FieldRule.Type
            , optional = base.frontmatter.recommended
            }
        }
```

— it is now a no-op and should be deleted, leaving the descriptor a plain pinned
import. Deleting it changes nothing about which documents pass. Keep any *other*
customization the project layered on.

## Change the pin

Set the import in `docs/adr/profile.dhall` to the v0.8.0 tag:

```dhall
let Profiles =
      https://raw.githubusercontent.com/shinzui/okf-profiles/v0.8.0/package.dhall
```

The blueprint ships the target descriptor as
`architecture-decisions-profile.dhall` in the reference directory. If the
project's existing descriptor has no customizations beyond the presence override
described above, install the shipped file as-is. If it has others, change the
tag by hand and keep them.

Re-freeze the integrity hash after editing — the hash must match the new tag:

```sh
dhall freeze docs/adr/profile.dhall
```

Never hand-write a `sha256:` value, and never delete the hash to make an import
resolve. (`--inplace` is deprecated as of dhall 1.42.3; freezing is in-place by
default.)

## Bring the corpus up to OKF v0.2

Work from the validator's output, not from assumption. Re-run the check after
the pin change and fix what it reports.

**Add `generated` to every ADR.** Derive both members from evidence in the
repository, never from the current clock:

- **`at` comes from the document's existing `timestamp`.** That is precisely
  what `generated.at` supersedes, so reuse the value verbatim. Restamping to the
  current time destroys history and can break the `okf log` coverage gate, which
  now reads `generated.at` in preference to `timestamp`.
- **If a document has no `timestamp`**, use the last commit that meaningfully
  changed that file:

  ```sh
  git log -1 --format=%cI -- docs/adr/<file>.md
  ```

  Convert that to the `Z` form, preserving the instant.
- **`by` comes from authorship.** The git author of the commit that created the
  file becomes `human:<id>`, using the identifier the repository already uses for
  that person elsewhere. A document that names the tool that generated it becomes
  `<producer>/<version>`. If a document was clearly produced by an automated
  process the repository runs, use `process:<name>`. When the evidence is
  genuinely ambiguous, prefer the git author over inventing a producer.

Keep `timestamp` where it exists. Adding `generated` beside it is the whole
change.

**Declare the bundle version:**

```sh
okf index docs/adr --write --okf-version 0.2
```

This generates an `index.md` per directory and writes `okf_version: "0.2"` into
the root one only. It overwrites exactly what it generates, never deletes, and
preserves an existing declaration on a re-run, so it is safe to run repeatedly.
Note that it does **not** notice that a previously indexed file has moved — if
you relocated anything, delete the stale index and regenerate.

**Delete the redundant presence override** if the descriptor carries it, as
described above.

## Scope

This edge covers the architecture-decision bundle only. If the repository has
other OKF bundles — research documents, improvement requests, use cases, a
pattern catalog, a PostgreSQL description — they have their own profiles and are
**not** in scope here. Every one of them needs the same v0.2 migration, and the
blueprint that does it is **`migrate-okf-bundles-to-v0-2`**, which detects
whichever profiled bundles a repository has and migrates them all:

```sh
seihou agent run migrate-okf-bundles-to-v0-2
```

Name it in your summary if you find such a bundle. Do not touch it here.

## Do not

- **Do not rewrite `status` values.** An ADR's `status: Accepted` is this
  profile's house lifecycle vocabulary. OKF v0.2 §5.4 defines a `status` key
  with the values `draft` / `stable` / `deprecated`, and the architecture-decision
  profile deliberately does **not** adopt it — the key name is shared, the
  meaning is not. Rewriting `Accepted` to `stable` would destroy the corpus's
  lifecycle information and break every downstream query, and nothing in v0.8.0
  asks for it.
- **Do not delete `timestamp`.** It is demoted to `optional`, not removed.
- **Do not restamp `timestamp` or invent a `generated.at`.** Both come from the
  document's own history.
- Do not weaken the profile to make the corpus pass. Deleting the now-redundant
  presence override is the only sanctioned descriptor change beyond the tag; do
  not move `type`, `title`, `docId`, `status`, `date`, `description`, or
  `generated` out of `required`, and do not drop `--strict` from the check.
- Do not rewrite ADR prose. This edge touches frontmatter, the descriptor, and
  the bundle index.
- Do not renumber ADRs to close gaps.
- Do not add `sources`, `usage_window`, `stale_after`, or a `trust` key. The ADR
  profile declares none of them, and a document's trust tier is derived from
  `verified` on every read rather than written into the bundle.

## Before you finish

Run the repository's ADR check and confirm it passes:

```sh
okf validate docs/adr --strict --profile docs/adr/profile.dhall \
  --profile-enforce --log-enforce
```

A passing run reports the version declaration, which is how you know the bundle
index took effect:

```text
OK: 12 concepts (okf_version 0.2)
```

If `log.md` exists and the check reports stale log coverage — `generated date
<date> has no enclosing log.md` — append a dated entry describing this upgrade:

```sh
okf log add docs/adr --kind Migration -m "Move the ADR bundle to OKF v0.2." --date <date>
```

Report: the tag moved from and to, how many concepts now validate, every
document whose frontmatter you changed and which field, where each `generated.by`
value came from, whether you deleted the presence override, any other OKF bundle
you found and left alone, and anything you could not resolve.
